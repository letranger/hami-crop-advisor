藏鑰匙 ① 程式碼裡沒有鑰匙，鑰匙只在 Vercel

手機只跟自己的後端講話，後端才拿鑰匙去找 AI

農友手機（app.js）

fetch('/api/ask', {question})

看得到原始碼，但裡面沒有任何金鑰

Vercel 後端（api/_rag.js）

process.env.GROQ_API_KEY

執行時才從環境變數讀鑰匙，外人看不到

Groq / Gemini

Authorization: Bearer gsk_…

只有後端對 AI 的這一段才帶鑰匙

✗ 錯誤寫法（在 app.js）

const KEY = 'gsk_abc123…';
fetch('https://api.groq.com/…', {headers:{Authorization:'Bearer '+KEY}})

任何人按「檢視原始碼」就拿走你的鑰匙，額度被刷光

✓ 正確寫法（在 api/_rag.js）

const k = process.env.GROQ_API_KEY;
if (!k) throw new Error('伺服器未設定 GROQ_API_KEY');

鑰匙的「值」從來不出現在程式碼，只出現在 Vercel 設定裡

技術細節 8 / 12 · 這就是步驟 7 說「不用 GitHub Pages」的真正原因

第四件事，也是最重要的：藏鑰匙。原則一句話：手機只跟我們自己的後端講話，後端才拿鑰匙去找 AI。左邊是農友手機上跑的 app.js，它只呼叫 /api/ask，任何人都看得到這段原始碼，但裡面沒有任何金鑰。中間是 Vercel 上的後端 api/_rag.js，程式執行時才用 process.env.GROQ_API_KEY 從環境變數讀出鑰匙，外人看不到。右邊是後端對 Groq 或 Gemini 的請求，只有這一段才帶著鑰匙。下面對比錯誤和正確寫法：錯的是把 gsk 那串直接寫在 app.js 裡，任何人按檢視原始碼就拿走，額度一下就被刷光；對的是程式碼裡只寫名字 GROQ_API_KEY，值永遠只在 Vercel 設定裡。這也是前面說不能只用 GitHub Pages 的真正原因，Pages 沒有後端可以藏鑰匙。
