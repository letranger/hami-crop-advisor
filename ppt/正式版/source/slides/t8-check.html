藏鑰匙 ② 三道保險，和怎麼自己檢查

本機用 .env、雲端用環境變數、GitHub 永遠沒有

① 本機測試 → .env

鑰匙寫在自己電腦的 .env 檔，npx vercel dev 會讀它

② .gitignore 擋住

.env
.env.*
!.env.example

git 永遠不會把 .env 送上 GitHub

③ 只給範本

GEMINI_API_KEY=
GROQ_API_KEY=
TAVILY_API_KEY=

.env.example 進版控，只有名字沒有值

上線前自己檢查（三分鐘）

在網站按右鍵「檢視原始碼」，搜尋 gsk_ 和 AIza：要找不到

到 GitHub 儲存庫搜尋同樣兩個字串：要找不到

萬一真的推上去了：立刻到該網站刪掉那把、重建一把，改歷史紀錄沒用

技術細節 9 / 12

最後是三道保險，還有怎麼自己檢查。第一，本機測試時鑰匙寫在電腦上的 .env 檔，npx vercel dev 會自動讀它。第二，.gitignore 裡把 .env 擋住，git 永遠不會把它送上 GitHub。第三，進版控的只有 .env.example 這個範本，只有名字沒有值，讓接手的人知道要設哪幾個。上線前花三分鐘自己檢查：到網站按右鍵檢視原始碼，搜 gsk 底線和 AIza，要找不到；到 GitHub 儲存庫搜同樣的字串，也要找不到。萬一真的不小心推上去了，不要想說改歷史紀錄就好，GitHub 上的東西一推出去就當作已經被看到，正確做法是立刻到該網站刪掉那把鑰匙、重建一把、更新 Vercel。技術細節到這裡，接下來回到除錯的故事。
